Thread

A lightweight service framework for Roblox

A clean Service Architecture, a typed Communication System, and a small Promise implementation for startup sequencing — every file is plain, hand-written .luau. No Wally, no package manager, no third-party code.

Why Thread

Thread lets you define services (server) and controllers (client) with a two-phase lifecycle, then expose typed methods, signals, and properties to clients without manually wiring up a single RemoteEvent. The server's Client table is the API the client gets back — no string-matching two ends by hand.

In one line
Similar shape to Knit (services, Client tables, Promise-based startup), but with built-in rate limiting, invoke timeouts, dependency ordering, and zero external dependencies — see the CHANGELOG for the full version history.

Quick Start

-- ServerScriptService/Server.server.lua
local Thread = require(game:GetService("ReplicatedStorage").Packages.Thread)

Thread.Register(game:GetService("ServerScriptService").Services)
Thread.Start():catch(warn)
-- ServerScriptService/Services/MoneyService.luau
local Thread = require(game:GetService("ReplicatedStorage").Packages.Thread)

local MoneyService = Thread.CreateService({
    Name = "MoneyService",
    Client = {
        GetMoney = function(self, player)
            return self.Server:GetMoney(player)
        end,
        MoneyChanged = Thread.CreateSignal(),
        Jackpot = Thread.CreateProperty(0),
    },
})

local balances = {}

function MoneyService:GetMoney(player)
    return balances[player] or 0
end

return MoneyService

That's it — Channel.BuildClient("MoneyService") on the client gets back a proxy with a :GetMoney() method, a connectable MoneyChanged signal, and an observable Jackpot property, automatically.
