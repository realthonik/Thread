Server vs. Client Cheat Sheet

The single most important thing to internalize: the server and every client each run their own separate instance of Thread's internal state (Thread._Register, its own start Promise, etc.) — they are different Lua VMs entirely. Nothing about a service you create on the server is automatically visible to Thread.GetService on the client, or vice versa. Channel is the only bridge between the two.

I want to...On the serverOn the client
Define a service/controllerThread.CreateService({...})Thread.CreateService({...}) (same call, informally called a "controller")
Expose something to clientsGive the service a Client = {...} table— (nothing to expose from one client to others)
Get one of MY OWN registered servicesThread.GetService("X")Thread.GetService("X")
Get a server service's Client API— (already has direct access)Channel.BuildClient("X") — never Thread.GetService
Fire a signalself.Client.MySignal:Fire(player, ...) / :FireAll(...) / :FireExcept(p, ...)proxy.MySignal:Fire(...) (server inferred)
Read/set a property:Get() / :Set(v) / :SetFor(p, v) / :GetFor(p) / :ClearFor(p):Get() / :Observe(fn) only
A common mistake
[Thread] No service named 'ArrestService' is registered

This means you called Thread.GetService("ArrestService") on the client, but ArrestService was only ever created on the server. Use Channel.BuildClient("ArrestService") instead.

Exported Luau Types

Every module is written under --!strict and exports its own types, so if your own code also uses --!strict (or just wants editor autocomplete), you can reference them directly off the required module: 

local Thread = require(game:GetService("ReplicatedStorage").Packages.Thread)

local def: Thread.ServiceDef = {
    Name = "MoneyService",
    Client = { ... },
}

local MoneyService = Thread.CreateService(def)

Testing

A tiny, dependency-free test runner lives under Tests/ (no TestEZ, no Wally — just pcall + assert).

  1. Copy the Thread/ and Tests/ folders into your Rojo project (or Studio, as siblings), so Tests/Thread.spec.luau can reach ../Packages.
  2. Start a Play/Test session in Studio, then paste into the Command Bar: 
    require(game.ServerScriptService.Tests["Thread.spec"])
  3. Read the Output window — [PASS]/[FAIL] per test case, with a summary line at the end.

Troubleshooting

No service named 'X' is registered

You're calling Thread.GetService for a service that isn't registered on that side. If X is a server-only service and you're on the client, use Channel.BuildClient("X") instead.

Remote/service marker timeout errors

'<Name>' does not exist after waiting <N>s / Service '<Name>' was never wired by the server — the client is waiting for a Remote/service marker the server never created. Usually a race condition (client called Channel.BuildClient before the server's Thread.Start() ran) or a misspelled service name.

A critical service's failure didn't crash my script

That's the default, intentional behavior. Handle it via Thread.Start():catch(...), or opt back into the old behavior with Thread.Configure({ HaltOnCriticalFailure = true }).

Rate limit warnings in the output

A player is calling a Method/Signal faster than the configured limit — either legitimate rapid input (raise the limit via RateLimit/InvokeRateLimit) or exploit/spam attempts (leave it, that's the protection working).

Duplicate service name error

Two different ModuleScripts called Thread.CreateService({ Name = "X" }) with the same name — names must be unique per side.
